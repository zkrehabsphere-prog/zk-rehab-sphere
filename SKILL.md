# Complete Project Skill

Purpose
-------
This workspace-scoped skill codifies a repeatable workflow for working with the complete ZK_Rehab_Sphere_Project repository: common setup, local development, database seeding, basic verification, and deployment guidance.

When to use
-----------
- Use when onboarding, running the project locally, seeding demo data, or preparing a deployment.
- Workspace-scoped: assumes the repo root contains `backend/`, `frontend/`, and top-level config files.

Inputs
------
- Target environment: `development` or `production`.
- Secrets/config: database URI, Firebase creds, Vercel token (as needed).

Workflow (step-by-step)
----------------------
1. Install dependencies
   - Run `npm install` in the repo root and inside `backend/` and `frontend/` when required.
2. Configure environment
   - Ensure `.env` or environment variables are set for DB, Firebase, and any API keys.
   - If unsure, consult `config/` for expected vars.
3. Seed the database (optional)
   - Run `node backend/seed.js` (or the repository's documented seeding command).
   - Branch: if using a cloud DB, confirm safe seeding mode (do not destroy production data).
4. Start backend
   - Run the backend with `node backend/server.js` or `npm run start` from `backend/`.
5. Start frontend
   - From `frontend/` run `npm run dev` (or the repo's dev command) and verify the UI loads.
6. Verify basic health checks
   - Confirm backend logs show a listening port and DB connection.
   - Open the frontend and confirm API endpoints return expected responses.
7. Build & deploy
   - For deployment, use the documented provider (`vercel.json` present) or follow CI steps.

Decision points and branching
----------------------------
- Local vs cloud DB: choose safe seeding and configuration depending on the environment.
- Deploy target: if deploying to Vercel, prefer the repository's `vercel.json` settings; otherwise adapt to chosen host.

Quality criteria / completion checks
---------------------------------
- Backend connects to DB without errors.
- Seed script inserts demo data and the API returns seeded records.
- Frontend loads and can fetch data from backend endpoints.
- Lint/build steps complete without critical errors (if present).
